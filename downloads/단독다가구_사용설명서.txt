# 단독·다가구 실거래가 수집 및 주소 후보 분석

첨부된 9개 코드의 수집·대장 비교·좌표·파생변수·저장 흐름을 **단독·다가구 매매용**으로 정리했습니다. 실제 실행 코드는 `single_multi_house.py` 한 파일이며, 실행 조건만 `config.json`에 둡니다. Python 3.10 이상이면 별도 패키지 설치 없이 실행합니다. Windows, macOS, Linux에서 사용할 수 있습니다.

주소의 `**`를 원상 복구하는 기능은 아닙니다. 공개된 지번 패턴과 건축물대장의 연면적·대지면적·사용승인연도를 비교해 **미확정 주소 후보**를 출력합니다. 점수는 정답 확률이 아닙니다.

## 1. 실행

압축을 풀고 해당 폴더에서 터미널 또는 명령 프롬프트를 여세요.

```bash
python single_multi_house.py --demo
```

가상 지역·합성 거래 예제이며 API 키나 인터넷이 필요 없습니다. 거래 7건, 후보 8행을 저장합니다. 미매칭·취소거래도 거래 요약에는 남습니다. 예제의 지역코드와 주소는 실제 지역이 아닙니다.

실제 자료는 `config.json`을 수정한 후 실행합니다.

```bash
python single_multi_house.py
```

Windows에서 `python` 명령이 없다면 `py -3 single_multi_house.py`를 사용하세요. IPython/Jupyter에서는 `!python ...` 대신 터미널 실행을 권장합니다. 별표 입력조차 표시되지 않는 `getpass` 프롬프트가 사용됩니다.

실행 시 입력 순서:

1. 공공데이터포털 인증키 입력.
2. 실거래가 수집 완료 후 건축물대장 인증키 입력. 같은 키면 Enter.
3. `geocode: true`인 경우에만 별도의 VWorld 키 입력.

인증키는 실행 중 메모리에서만 사용합니다. 설정·캐시·결과·오류 메시지에 저장하지 않습니다. Encoding/Decoding 인증키를 모두 받으며 `+`가 공백으로 변하지 않게 처리합니다. 키를 명령줄 인수로 받지 않습니다.

## 2. 조회기간·지역 여러 개 설정

`config.json`은 JSON 형식이므로 주석을 넣지 마세요. 아래처럼 시군구 객체와 법정동 객체를 추가합니다.

```json
{
  "start_month": "202501",
  "end_month": "202512",
  "areas": [
    {
      "sido": "경기도",
      "sigungu": "용인시 수지구",
      "sigungu_code": "41465",
      "legal_dongs": [
        {"name": "풍덕천동", "code": "4146510100"},
        {"name": "상현동", "code": "4146510700"}
      ]
    },
    {
      "sido": "서울특별시",
      "sigungu": "마포구",
      "sigungu_code": "11440",
      "legal_dongs": [
        {"name": "연남동", "code": "1144012400"}
      ]
    }
  ],
  "matching": {
    "top_n": 5,
    "min_score": 40,
    "max_year_gap": 10,
    "ambiguity_gap": 5,
    "mask_mode": "digit_count",
    "include_cancelled": false
  },
  "cache_hours": 24,
  "geocode": false,
  "output_dir": "results"
}
```

- 시작월·종료월을 **모두 포함**하는 연속 기간입니다. 종료월은 현재월 이하여야 합니다. 현재월 자료는 신고 지연으로 미완결일 수 있습니다.
- 떨어진 여러 기간도 조회할 수 있습니다. 이때 최상위 `start_month`, `end_month`를 제거하고 대신 `"periods": [{"start_month": "202401", "end_month": "202403"}, {"start_month": "202501", "end_month": "202503"}]`를 넣습니다. 겹치는 월은 한 번만 수집합니다.
- `areas`에 여러 시군구, `legal_dongs`에 여러 법정동을 넣습니다. **상현동**은 법정동이고 **상현1동**은 행정동입니다. 이 프로그램은 요청에 따라 법정동만 사용합니다.
- 같은 시군구·월의 실거래가는 한 번만 수집한 후 법정동으로 필터링합니다. 중복 선택한 법정동은 한 번만 처리합니다.
- 시군구는 5자리, 법정동은 10자리 공식 코드를 **따옴표 안의 문자열**로 넣습니다. 지역 개편·폐지코드는 실행 전에 확인하세요. 코드를 직접 넣으면 이름과 코드의 실제 공식 대응을 원격 검증하지는 않으므로 둘을 정확히 맞춰야 합니다. 입력된 코드의 시군구 앞 5자리 일치는 검사합니다.
- 법정동 `code`를 `""`로 비우면 `시도 + 시군구 + 법정동`의 공식 명칭으로 자동조회합니다. 이때만 **행정안전부 법정동코드 조회 API 활용신청**이 추가로 필요합니다. 검색 결과가 없거나 모호하면 임의 첫 번째 결과를 쓰지 않고 중단합니다.
- 같은 시군구에 동일 이름의 리가 여러 개이고 원자료가 이를 구별할 코드를 제공하지 않으면 모호성 오류로 중단합니다. 코드를 추측해 연결하지 않습니다.
- 제공한 `examples/multiple_regions.json`도 다중 지역 설정 예제입니다.

```bash
python single_multi_house.py --config examples/multiple_regions.json
```

`output_dir`은 **설정 파일 위치 기준**의 경로입니다. API 캐시는 그 안의 `cache/`, 결과는 매번 새 실행시각 폴더에 저장합니다. 다른 실행의 결과를 덮어쓰지 않습니다.

## 3. 어떤 기준으로 후보를 고르는가

1. **10자리 법정동코드 일치**: 이름이 같더라도 다른 시군구 자료는 섞지 않습니다.
2. **일반 단독·다가구 대장만 비교**: 건축물대장 `getBrTitleInfo`의 표제부를 사용합니다. 집합건축물·아파트·다세대·연립·전유부는 제외합니다. 단독주택·다가구·다중주택·공관 용도만 대상으로 하며, 기타용도도 확인합니다.
3. **지번 패턴 일치**: 산/일반 대지 구분을 고정합니다. `12*`는 기본적으로 본번 세 자리 중 `12`로 시작하는 후보를 비교합니다. 공개 본번만 있는 마스킹 자료는 부번이 생략됐을 수 있어 `123-4`도 후보가 됩니다. `12*-*`처럼 공개 부번 패턴이 있으면 부번도 비교합니다. 완전 공개 지번 `123`은 `123-4`와 연결하지 않습니다.
4. **연면적 40점 + 대지면적 30점 + 건축년도 20점 + 유형 10점**으로 총 100점 비교합니다. 면적은 0.1㎡ 이내 차이를 허용하고 그 외에는 상대 오차 20%에서 0점이 되는 선형 점수를 사용합니다. 건축년도는 정확히 같으면 20점, 1년 차이마다 4점 감소합니다. `max_year_gap`보다 큰 차이는 후보에서 제외합니다.
5. 같은 지번의 여러 일반건축물 동은 개별 표제부의 연면적을 합산한 **지번 전체 거래 가설** 하나로 비교합니다. 대지면적은 중복 합산하지 않습니다. 동마다 대지면적이 다르거나 일부 누락되면 해당 면적은 점수에 쓰지 않습니다. 복수동 합산은 경고를 남기고 고유사 판정을 제한합니다. 주건축물·부속건축물이나 증축 이력 때문에 합산값이 거래면적과 다를 수 있습니다.
6. 전체 기준통과 후보에서 순위·동점·1~2순위 점수 차이를 먼저 계산하고, 이후 상위 `top_n`개만 후보 파일에 표시합니다. 따라서 `top_n: 1`도 동점 후보가 유일 후보로 바뀌지 않습니다.

| 설정 | 기본값 | 의미 |
|---|---:|---|
| `top_n` | 5 | 거래별 표시할 후보 수 |
| `min_score` | 40 | 후보로 출력할 최소 점수 |
| `max_year_gap` | 10 | 거래 건축년도와 대장 사용승인연도 간 허용 차이 |
| `ambiguity_gap` | 5 | 1~2순위 점수 차이가 이 값 미만이면 구분 어려움 표시 |
| `mask_mode` | `digit_count` | 별표 1개를 숫자 1자리로 해석 |
| `include_cancelled` | false | 취소거래를 매칭에 포함할지 여부 |

API의 별표 개수가 원래 자리수를 뜻한다는 가정은 **해당 자료에 맞는지 확인**해야 합니다. 자리수 의미가 없는 자료라면 `mask_mode: "wildcard"`로 바꿀 수 있습니다. 이 모드는 별표를 0개 이상의 숫자로 보므로 후보 범위가 넓어집니다. 기본 모드에서 매칭되지 않아도 지역·산 여부·지번 길이 조건을 자동 완화하지 않습니다.

누락된 면적·연도에는 0점을 부여하며, 남은 항목만으로 100점으로 환산하지 않습니다. `비교가능가중치`를 함께 확인하세요. `**`처럼 숫자가 전혀 없는 지번은 면적이 같아도 상대적 고유사로 표시하지 않습니다. 어떤 상태이든 `주소확정여부`는 **미확정**입니다. 이 점수와 기준은 경험적 비교 규칙이며 실제 정답 주소를 이용해 통계적으로 검증한 모델은 아닙니다.

현재 건축물대장을 과거 거래와 비교하므로 철거·신축·증축·필지분할·합병·지번변경·지분거래·복수동 중 일부 매매는 대응되지 않을 수 있습니다. 거래의 건축년도와 대장의 사용승인연도도 완전히 같은 개념은 아닙니다. 실거래가의 가격은 후보 순위에 사용하지 않습니다.

## 4. 생성 파일

| 파일 | 내용 |
|---|---|
| `single_multi_house_trade.csv` | 선택 기간·법정동의 거래 원자료 정리. 취소거래와 동일 속성의 복수 거래도 유지 |
| `trade_summary.csv` | 거래 한 건당 한 행. 1순위 후보·점수 차이·미매칭 사유·취소제외 상태 |
| `address_candidates.csv` | 거래별 상위 후보와 항목별 점수·면적 차이·대장 정보 |
| `analysis.sqlite` | 위 세 파일에 대응하는 `single_multi_house_trade`, `trade_summary`, `address_candidates` 테이블 |
| `raw_trades.json` | 실제 수집/입력한 실거래가 원자료. 시군구 전체 원자료이므로 선택하지 않은 법정동도 포함 가능 |
| `raw_building_titles.json` | 건축물대장 표제부 원자료 |
| `run_info.json` | 조회 설정, 거래 건수, 원자료 수집시각·캐시 사용 여부, 매칭 상태별 건수·경고 |
| `qgis_candidates.geojson` | 좌표 기능 사용 시 좌표가 있는 주소 후보만 생성. EPSG:4326 |

CSV는 Excel에서 열기 좋은 UTF-8 BOM 형식입니다. SQLite는 가격·점수·면적을 수치형으로 저장합니다. XLSX 출력에 필요한 패키지는 요구하지 않습니다.

파생변수는 거래금액(원), 면적(평), 연면적/대지㎡당 거래금액(만원), 계약 당시 경과연수입니다. **대지㎡당 거래금액은 토지·건물 합계 거래대금을 대지면적으로 나눈 값**으로 순수 토지가격이 아닙니다. 취소거래도 원자료와 요약에 남으므로 가격 분석 시 `취소거래`를 확인하세요.

공식 고유 거래 식별자가 없어 원자료의 해시와 같은 행의 발생 순번으로 `거래ID`를 만듭니다. 속성이 같은 별개의 거래를 임의 삭제하지 않습니다. API 응답이 수정되거나 로컬 자료 형태가 바뀌면 이 ID도 달라질 수 있으므로 영구적인 거래 ID나 실행 간 갱신 키로 쓰지 마세요. 각 실행은 독립 스냅샷입니다. 주소를 나중에 계약일·금액 등으로 다시 붙이는 다대다 조인 단계는 필요 없습니다.

## 5. 기존 CSV·SQLite 재사용

첨부 수집 코드에서 만든 자료도 아래처럼 읽습니다. 한쪽만 지정하면 다른 쪽은 API로 수집합니다. 경로는 **명령을 실행한 현재 폴더 기준**입니다.

```bash
python single_multi_house.py --trade-source "기존_단독다가구.sqlite" --building-source "building_register_matching.db"
```

기본 테이블은 실거래가 `single_multi_house_trade`, 건축물대장 `building_title_all`입니다. 다른 이름이면 `--trade-table`, `--building-table`을 지정하세요. SQLite는 읽기 전용으로 엽니다. CSV는 UTF-8 BOM 또는 CP949를 자동 구분합니다.

```bash
python single_multi_house.py --trade-source "거래.csv" --building-source "표제부.csv"
```

지원하는 주요 컬럼:

- 거래: API 원래의 `sggCd, umdNm, jibun, dealYear, dealMonth, dealDay, dealAmount, houseType, totalFloorAr, plottageAr, buildYear` 또는 첨부 코드의 `지역코드, 법정동, 지번_마스킹, 계약년, 계약월, 계약일_일, 거래금액_만원, 주택유형, 연면적_㎡, 대지면적_㎡, 건축년도`.
- 대장: API 표제부의 `sigunguCd, bjdongCd, platGbCd, bun, ji, regstrGbCd, mgmBldrgstPk, platPlc, newPlatPlc, mainPurpsCdNm, etcPurps, totArea, platArea, useAprDay` 또는 첨부 DB의 `sigungu_cd, bjdong_cd, plat_gb_cd, bun, ji, regstr_gb_cd, bld_key, plat_plc, new_plat_plc, main_purps_cd_nm, etc_purps, tot_area, plat_area, use_apr_day`.

지역코드가 없는 자료를 지역 이름만으로 다른 시군구에 연결하지 않습니다. 기존 자료만 분석할 때는 모든 법정동의 10자리 코드를 설정해 주세요. 입력 파일의 전체 기간/대장 수집 완전성은 별도로 확인해야 하며, 로컬 파일이 API 전체 자료라는 보장은 하지 않습니다.

## 6. 캐시·좌표·오류

기본 캐시는 수집 후 24시간 유효합니다. `run_info.json`에서 원자료 수집시각(UTC)을 확인할 수 있습니다. 계약 해제·정정까지 최신 자료를 받으려면 다음 명령을 사용하세요.

```bash
python single_multi_house.py --refresh
```

`cache_hours: 0`도 캐시 재사용을 끕니다. 페이지 전체 건수 검증이 끝난 응답만 캐시에 저장합니다. 응답 페이지 불일치·중간 빈 페이지·반복 페이지·수집 중 전체 건수 변경은 오류로 처리하며 부분 데이터를 정상 결과로 저장하지 않습니다. HTTP 429/일시적 서버 오류/연결 지연은 제한적으로 재시도합니다. 인증 오류를 빈 거래로 처리하거나 TLS 검증을 끄지 않습니다.

필수 활용신청과 네트워크 목적지:

- 국토교통부 단독/다가구 매매 실거래가 자료: `apis.data.go.kr/1613000/RTMSDataSvcSHTrade/getRTMSDataSvcSHTrade`
- 건축HUB 건축물대장정보 표제부: `apis.data.go.kr/1613000/BldRgstHubService/getBrTitleInfo`
- 코드 자동조회 시에만 행정안전부 법정동코드: `apis.data.go.kr/1741000/StanReginCd/getStanReginCdList`
- 좌표 사용 시에만 VWorld: `api.vworld.kr/req/address`

인증키 하나여도 **서비스별 활용승인**이 필요할 수 있습니다. 이 환경에서 인터넷이 제한되면 `apis.data.go.kr`을 네트워크 허용 목록에 추가해야 합니다. 좌표를 사용하면 `api.vworld.kr`도 추가해야 합니다. 키는 환경 설정에 저장할 필요 없이 매번 수동 입력합니다.

`geocode: true`는 VWorld로 후보의 지번주소를 좌표화합니다. 지리좌표는 **후보 건물의 좌표**이며 해당 거래의 실제 위치가 확인됐다는 뜻이 아닙니다. 동일 주소는 한 실행 내 한 번만 조회합니다. 좌표 API 실패 시 수집·매칭 결과는 저장하고 좌표 실패 상태와 종료코드 2를 남깁니다. 좌표가 정상 검색됐어도 주소 후보 점수를 올리지 않습니다. QGIS에서는 GeoJSON을 바로 열거나 후보 CSV의 경도·위도를 X/Y로 지정하세요.

## 7. 코드 구조와 검증

`main()` → `run()`에서 순서대로 실행합니다.

- `resolve_scopes()`: 법정동코드 정리
- `ApiClient.collect()`: 페이지 수집·재시도·전체 건수 검증·캐시
- `make_trade_rows()`, `make_buildings()`: 원자료 정리·지번별 대장 집계
- `match_trades()`, `score_candidate()`: 후보 비교·모호성 판단
- `add_coordinates()`: 선택적 좌표 생성
- `export_results()`: CSV·SQLite·원자료·실행정보 저장

첨부 상업·업무용 코드의 전유부 묶음·층 비교는 단독·다가구 전체건물 거래에 맞지 않아 사용하지 않았습니다. 도로명은 표제부 후보 정보로 바로 결합하므로 별도 엑셀 주소 병합 작업이 없습니다. Windows 개인 폴더 경로와 전역 키를 제거하고 조회 조건을 설정 파일로 분리했습니다.

검증 명령:

```bash
python -m unittest discover -s tests -v
python single_multi_house.py --demo
```

자동 검증은 합성 자료와 모의 API 응답을 사용합니다. 기간·다중 지역 격리·중복 거래 보존·산지번·별표 패턴·복수동 집계·결측값·취소거래·동점·페이지 누락·캐시·인증키 비노출·SQLite 재입력·전체 파일 저장을 확인합니다. **사용자의 실제 키로 외부 API를 호출하거나 실주소 정답률을 검증한 것은 아닙니다.**
